The explicit maps in `skill-export.json` and `plugin-export.json` are the complete export allowlists. Each file's origin, SHA-256 and normalized mode appears in the corresponding manifest. Plugin packaging adds only three mapped root files: existing manifest, license, dependencies. The nested skill matches the standalone selection byte for byte. Source files with executable bits normalize to 0755, others to 0644; ownership, ACLs and extended attributes are not preserved.

Both `__pycache__` entries are intentionally excluded. Also excluded: workspace instructions, skill-delivery/authoring workflows, source-record/input inventory, internal logs, evaluation rubric, local skills lock, official documentation snapshots and unrelated files. The supplied lock pins a local skill-delivery path; it is not an editorial consumer pin and must not be shared as an installation lock.

Manual inspection of the 12 skill files and manifest found synthetic examples, ordinary public attribution URLs, no customer manuscripts, private project briefs, credentials or dependency on another Foculoom product. The export helper also applied its narrow secret and denied-path screen. These bounded checks do not prove absence of secrets, privacy compliance or publication rights. Keep the entire evidence packet internal until separately cleared; distribute only the reviewed payload and an approved public description.

No additional required portable environment constraint was discovered, so no speculative compatibility metadata was added. The existing dependency record already explains optional Python and fallback behavior. Remote release identity, publication rights and client compatibility remain distinct questions.
