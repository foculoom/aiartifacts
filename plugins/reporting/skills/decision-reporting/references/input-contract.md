# Normalized input contract (version 1)

The helper accepts one JSON document. It makes no network calls. Use authorized exports/connectors and write private input files with restrictive permissions. All timestamps must include timezone; the reporting interval is start-inclusive, end-exclusive.

- `window`: `start`, `end`; `as_of` is at or after end.
- `config`: `products`, `contact_types`, `themes` arrays of approved lowercase slugs (letters, digits, underscore, hyphen; max 48 characters), and optional `max_source_age_hours` (default 48). Optional `editions` and `builds` arrays approve normalized product-edition/build slugs; for example `three-room` and `ios-1_0-3`. Normalize raw version strings upstream. Optional `pages`, `referrers`, `devices` slug arrays approve analytics categories (for example home/support, direct/search/social, desktop/mobile). These categories are not source text.
- `sources`: fixed keys `tally`, `gmail`, `analytics`. Omitted sources are unavailable.
- Each source has `status` (`ok`, otherwise unavailable), `fetched_at`, and `coverage` with start/end. `ok` attests the export covers the entire interval, including pagination; source adapters must not mark truncated searches complete. Old/future fetch times are stale. Incomplete interval coverage is partial.
- Tally/Gmail sources contain `records`: `id`, `created_at`, `product`, `contact_type`, `theme`, `status` (`open`, `resolved`, `unknown`), `is_qa` boolean. Unknown product/contact/theme categories become `unclassified`. Omitted triage status remains `unknown`, not resolved. IDs stay internal.
- Optional `usage_context` is one of `free_used`, `paid_used`, `pre_use`, `qa`, `owner_test`, `unknown`. Omission becomes `unknown`; never infer actual use or a customer from a missing answer. `free_used` and `paid_used` mean the source reported using that edition, **not** a verified purchase, entitlement or unique customer. `pre_use` is contact before reported use. `qa` and `owner_test` are excluded from feedback counts, as are records with `is_qa: true`; tag them upstream and preserve them in the source system. Invalid values invalidate the source.
- Optional `edition` and `build` are normalized slugs approved in `config.editions` and `config.builds`. Omission/null becomes `unknown`; an unapproved value becomes `unclassified`, without reproducing raw text in output. These labels identify the reported experience and artifact; they do not validate acquisition, installation, or purchase. Do not encode names, emails, exact customer IDs, or sensitive data in approved slugs.
- Gmail can have `submission_id`, referencing Tally's submission ID. All linked notifications are excluded; missing matching Tally records are separately counted as unmatched. For direct support mail, normalize one record per thread/case, using the original case timestamp, not each reply. Include older open cases when available. Do not infer resolved status from archive/read status.
- Analytics contains `metrics`: optional nonnegative numbers `visits`, `page_views`, `lcp_p75_ms`, `inp_p75_ms`, `cls_p75`. Missing metrics are null. Optional `dimensions` contains `pages`, `referrers`, `devices` objects mapping configured category slugs to nonnegative integer counts. Normalize provider page paths, referral hosts, and device classes to these approved categories before input; never retain raw URLs. Unknown categories are aggregated into `unclassified`. Omitted dimensions stay null; an observed empty breakdown is `{}`. Document the count unit (visits or page views) and any provider sampling/suppression in the private evidence note; do not add breakdowns together or claim they reconcile without evidence.

Source failures do not expose provider errors or arbitrary text in output. Invalid records invalidate their entire source, rather than silently undercounting. Outputs contain source status, normalized fetch timestamps, input counts, aggregate categories, exclusions, open-case age, fixed finding/action codes, and limitations. `by_usage_context`, `by_edition`, `by_build`, `actual_use` (`free_used` and `paid_used`), and `actual_use_by_product`/`actual_use_by_edition`/`actual_use_by_build` count included records only. They are partial observations whenever source coverage is incomplete. `actual_use` is self-reported use, not a buyer count. No input IDs or message text is emitted. Unavailable feedback sources cause `feedback.total = null`; `observed_records` is a partial count and must not be labeled a total. A complete empty import produces zero. The bundled synthetic fixture intentionally omits the optional experience fields to exercise legacy `unknown` behavior.

Reports are exclusively created with mode 0600; existing outputs are not overwritten. The caller selects a private directory, handles input permissions, collects source evidence, and implements approved retention/scheduling. The generator performs no deletions or scheduling.
