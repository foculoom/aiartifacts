# Interactive experiences

Inspect representative input, resulting state, recovery, and return/help paths. Preserve saved progress and platform conventions. Test keyboard and touch separately when possible; a canvas label alone does not establish accessible gameplay.

Review focus after dialogs, errors, loading, empty and unavailable states, and reduced motion where relevant. Use safe local fixtures for network failures and submissions. Record untested devices and incomplete journeys. Never turn synthetic data into claims about real forecasts, customers, or transactions.

For stateful interfaces, sample the journey as a sequence rather than a single screenshot:

1. **Starting:** identify the primary entry action, instructions and settings. Check whether actions that require an active session are hidden or visibly unavailable, while usable help remains reachable.
2. **Playing or working:** exercise each supported input separately and check feedback, focus, repeat behavior and the route back to help or settings.
3. **Overview or pause:** compare every visible action with its actual handler. Check that unavailable actions are conveyed as such and that the resume route is clear; preserve any recovery action that still works.
4. **Recovery:** exercise undo, restart, error return or reload as applicable, then verify retained state, focus and instructions. Do not infer persistence from a successful click alone.

Record the device or viewport, input method, exact artifact and observed result for each check. A browser-emulated viewport does not establish physical-device legibility or native behavior. For a dense overview, ask a target-device user to identify a relevant item and exit; fitting content on screen is not a readability criterion.

If released bytes, canonical source and an unpublished candidate differ, compare the relevant routes and actions across all three with exact revisions or hashes and observation dates. Keep a previously accepted candidate milestone even when a later change needs review. State which artifact a finding concerns, whether a public user can reach it now, and which release decision remains. Preserve existing routes and saved progress unless a change is authorized; do not turn an unrelated archived route into a new primary navigation action.
